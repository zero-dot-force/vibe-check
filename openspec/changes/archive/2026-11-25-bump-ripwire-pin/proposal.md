## Why

The ripwire-backed adapter (#69, PR #75) fails closed on anything but ripwire
`0.6.9` @ `bedc0cd`. Since that pin was validated, upstream has fixed all four
Python import-resolution gaps that the Phase 0 spike (#67) measured on pip:

| #478 gap | Fix | Upstream | First release |
|----------|-----|----------|---------------|
| 2 — `import a.b as c` never resolves | ours | redhat-et/ripwire#530 | v0.6.10 |
| 3 — crawl denylist prunes silently | maintainer | Train 44 (#485): `--skipped` rows + `<pruned_packages>` | v0.6.10 |
| 4 — stdlib-name collisions draw false sibling edges | maintainer | Train 44 (#485), plus src-layout resolution | v0.6.10 |
| 1 — wide-form `from pkg import mod` loses the member edge | ours | redhat-et/ripwire#533 | **v0.7.0** (0.6.11 was skipped) |

The spike's own ground truth puts the stakes plainly: django's Ce is 60% exact
without the wide-form fix and 100% with it. Users of `vibe-check analyze` on
Python projects get none of this until the pin moves, and the pin must name a
published release — a source build reports `0.6.10-dev.N+g<sha>` and must stay
refused.

The same releases also change the `--arch` surface the adapter parses
(ARCH-HONEST, Train 44): a module holding a file in a language ripwire draws
almost no file edges for (Go, Java, Kotlin, C#, PHP, Swift, Dart, GDScript,
Clojure) now reads `zone="unknown" no_file_edges=LANGS` with `ca`/`ce` as floors
or absent and no `I`/`D`/`reachable`, and `propagation_cost` can be absent. The
current parser treats every one of those attributes as required, so a Python
project carrying a single Go helper file would stop analyzing after a naive pin
bump. The bump is therefore a behavior change to the adapter, not a constant
edit.

## What Changes

- **Re-pin** `internal/ripwireadapter/version.go` to the first published
  ripwire release containing redhat-et/ripwire#533 (released as `0.7.0`), at its
  release commit. Skip `0.6.10` as an intermediate pin: it lacks fix 1, and
  every pin move re-records every golden. Fail-closed semantics are unchanged.
- **Narrow the `--arch` parse contract to what the adapter consumes**: the
  adapter reads only `path`, `ca`, `ce`, `types`, and `abstract` per row and
  derives `I`/`D`/zone itself via `metrics.Compute*`, yet the parser fails
  closed on `I`/`A`/`D`/`zone` and seven table aggregates it never uses —
  exactly the attributes ARCH-HONEST removes. Probed on a source build: a
  Python fixture with one `.go` file fails with `module row
  "fixturepy/cycle_a" missing I attribute`. The parser stops requiring
  unconsumed attributes; consumed ones stay fail-closed.
- **Map unknown coupling honestly**: a `zone="unknown"` row's `ca`/`ce` are
  floors (absent when no edge was observed — read as a zero floor, never as an
  exact zero). The graph carries a new `coupling-floor` warning naming the
  affected modules and the `no_file_edges=` languages (status `partial`, as for
  every warning).
- **Union the pruning disclosure**: the `denylist-pruned` warning lists the
  union of the existing filesystem pre-check and ripwire's own
  `<pruned_packages>` rows on `--arch`. ripwire rows only real packages (with
  `__init__.py`), so the pre-check stays for plain pruned directories (probed:
  a package-less `dist/` appears only under `--skipped`); ripwire's rows catch
  any upstream denylist change the hardcoded list has not caught up with.
- **Re-measure the error budgets** that `errorBudgetWarning` hardcodes (Python
  1.9% lost / 2.2% spurious; TypeScript 0.16% unresolved) on the spike's
  targets — pip @ `1000636` and rollup @ `ad39ddc` — against the new pin with a
  reproducible `ast`/path ground-truth harness, and update the warning text.
- **Re-record** every fixture recording, the fake-ripwire replay set, and the
  hand-computed goldens; add an ARCH-HONEST recording (a Python fixture with a
  Go file) so the new parse path is covered hermetically.
- **Development proceeds now** against a source build of ripwire `main`
  (≥ `1edb6fd`, which contains #533); only the final re-pin task waits for the
  release tag.

## Impact

- **Modified code**: `internal/ripwireadapter/` — `version.go` (pin),
  `parse_arch.go` (consumed-attribute contract, unknown rows,
  `<pruned_packages>`), `mapping.go` / `assembly.go` (floor flag + warning),
  `denylist.go` (union), `budget.go` (re-measured figures), GoDoc that names
  the pinned version; `testdata/recorded/**`, `testdata/README.md`, goldens,
  tests that hardcode `0.6.9`/`bedc0cd`; README, CHANGELOG, AGENTS.md pin
  mentions.
- **Unchanged**: `metrics/` (Layer 1), `modulegraph.schema.json`, verdict
  thresholds, report engine, `cmd/vibe-check` language detection, and the Go
  adapter. No new Go dependencies.
- **Output**: Python/TypeScript `ModuleGraph` values change (more edges found,
  fewer false ones), so a `diff` across the upgrade boundary can show coupling
  deltas that reflect measurement, not code. CHANGELOG MUST say so.
- **Users**: must install the new ripwire release; the absent/mismatch error
  already names the validated pair, so the guidance updates itself.
- **Release gating**: the PR cannot merge until upstream publishes a release
  containing #533. Everything else is developed and reviewed beforehand.
- **Follow-ups**: #76's acceptance criteria are already met upstream (#530 and
  #533 merged) and it can close independently of this change; #80/#81 content
  should cite the re-measured budgets; #68 (`--dump-graph`) is unaffected and
  stays open.
